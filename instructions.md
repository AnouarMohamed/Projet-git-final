# 🎯 OBJECTIF DU PROJET

À la fin du module, vous devez démontrer que vous êtes capables de :

- Travailler efficacement en équipe avec Git & GitHub
- Structurer un projet logiciel de manière professionnelle
- Implémenter des fonctionnalités propres et organisées
- Appliquer un refactoring et un design pattern pertinent
- Analyser et corriger des problèmes de qualité (Sonar)
- Transformer une solution technique en proposition business claire

---

# 👥 ORGANISATION & RÔLES

Chaque groupe doit répartir les responsabilités suivantes.

Les rôles peuvent être adaptés selon la taille du groupe.

---

## 🧱 1️⃣ Workflow & Release Manager

**Mission :** Garantir un workflow Git professionnel.

Responsabilités :

- Création et gestion des branches (feature, hotfix…)
- Utilisation obligatoire des Pull Requests
- Historique clair et structuré
- Gestion des merges
- Création du tag final (v1.0)

---

## 💻 2️⃣ Feature & AI Lead (Vibe Coder)

**Mission :** Développer les fonctionnalités principales.

Responsabilités :

- Implémentation du MVP (CRUD ou site présentatif)
- Intégration d’une fonctionnalité IA pertinente
- Code structuré, lisible et organisé
- Préparation de la démo fonctionnelle

---

## 🧹 3️⃣ Quality & Refactoring Lead

**Mission :** Améliorer la qualité du code.

Responsabilités :

- Identification des code smells
- Application d’un design pattern pertinent
- Analyse du rapport Sonar
- Correction d’au moins 2 issues
- Présentation du “avant / après”

---

## 📊 4️⃣ Business & Documentation Lead

**Mission :** Donner du sens au projet.

Responsabilités :

- Rédaction d’un README clair et structuré
- Description de l’architecture
- Préparation de l’offre commerciale
- Structuration du pitch final

---

# 📦 LIVRABLES OBLIGATOIRES

Le projet doit contenir :

1. Repository Git structuré
2. Branches feature + Pull Requests
3. 1 hotfix
4. MVP fonctionnel
5. 1 intégration IA
6. 1 design pattern appliqué (optionnel)
7. Correction d’au moins 2 issues Sonar
8. README professionnel
9. Offre commerciale
10. Présentation finale

---

# 📊 GRILLE D’ÉVALUATION – NOTE INDIVIDUELLE /20

La note finale de chaque étudiant est composée de :

- 🔹 Partie Groupe : /10
- 🔹 Partie Individuelle : /10

---

## 🧱 PARTIE GROUPE – /10

### Workflow Git – /3

- Branches structurées
- Pull Requests utilisées
- Historique clair
- Tag & hotfix corrects

### MVP & IA – /3

- Fonctionnalités opérationnelles
- IA intégrée correctement
- Code organisé

### Refactoring & Qualité – /4

- Design pattern pertinent
- Amélioration visible
- Analyse et correction Sonar

---

## 👤 PARTIE INDIVIDUELLE – /10

### Contribution visible – /4

- Minimum 2 commits identifiables
- Travail réel et identifiable
- Participation active

### Maîtrise du rôle – /4

L’étudiant doit être capable d’expliquer :

- Ce qu’il a réalisé
- Pourquoi ce choix
- Comment cela fonctionne

### Compréhension globale – /2

Capacité à répondre à des questions sur :

- Le workflow Git
- Le design pattern
- Les corrections Sonar
- L’architecture

# 🎤 STRUCTURE DE PRÉSENTATION (10–12 minutes)

1. 🎯 Problème du client

1. Présentation du client
2. Problème identifié
3. Solution proposée

6. Planning simplifié
7. Estimation budgétaire (simulation pédagogique)
